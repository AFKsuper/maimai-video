# Maimai 手机端 Termux 视频推送 Agent 新手保姆级教程

本工具运行在安卓手机的 **Termux** 环境中，用于在手机上管理 Maimai 预渲染视频，并在机器人需要发送全曲视频时，通过局域网/公网极速回传给服务器，彻底告别服务器 CPU 渲染慢、卡死的问题！

> **提示**：本 Agent 是**可选**的。日常最省事的用法是让手机 Chrome 打开服务器下发的
> `worker.html` 工作页，由浏览器现场逐帧编码 60fps MP4，**直接存进手机**
> （`/sdcard/Download/maimai/`），再由本 Agent 在群里点播时回传给服务器。
> 完整部署说明见 `docs/手机渲染部署指南.md`。
>
> **本 Agent 有两件事要做**：
> 1. 群里点播时，把手机里已有的 MP4 **回传给服务器**（发群必须用服务器上的文件）。
> 2. 平时常驻，让服务器知道这台手机在线。
>
> **不需要任何 `adb reverse`**。渲染页和落盘服务由手机本机的 `render_server.py`
> 提供（`127.0.0.1:8777` 渲染页 + `127.0.0.1:8780` 落盘），
> 跨网那一段是手机**主动出站**连服务器的 8778，因此服务器在云上、
> 手机在 4G、IP 会变，全都不影响。

---

## 零、运行机制原理（一句话了解）

- 你的安卓手机安装 Termux 后，只要把 Maimai 的 60fps MP4 视频放在手机里；
- 手机端 Agent 自动保持与机器人服务器的连接（后台保活、断线自动重连）；
- 当群里有人使用 `谱面确认` 时，服务器先查本地缓存，没有就向手机发起视频请求，手机瞬间秒级回传 MP4 视频并发送到 QQ 群！

## 一、手机端安装步骤（共 6 步，小白无痛上手）

### 第一步：在 Android 手机上安装 Termux

> ⚠️ **切勿从 Google Play 商店下载 Termux**（已停止更新，会导致无法安装任何软件）。

请选择以下任一官方渠道下载 Termux APK 并安装：
1. **GitHub 官方发布页**（推荐）：
   - 下载地址：https://github.com/termux/termux-app/releases
   - 找到最新版本的 `termux-app_v0.xxx+github-debug_universal.apk` 或 `arm64-v8a.apk` 下载安装。
2. **F-Droid 开源市场**：
   - 搜索 `Termux` 并下载安装：https://f-droid.org/packages/com.termux/

---

### 第二步：打开 Termux 并授予手机存储权限

打开手机上的 Termux 应用，在命令行光标处输入以下命令并回车：

```bash
termux-setup-storage
```

> **注意**：此时手机屏幕上会弹出一个系统权限申请对话框（“允许 Termux 访问设备上的照片、媒体内容和文件”），**请务必点击【允许】**！

---

### 第三步：安装 Python 环境

在 Termux 终端中直接复制运行以下命令（全自动安装，无需配置额外编译工具）：

```bash
pkg update && pkg install python -y
```

> 提示：如果更新过程中提示 `[Y/n]` 或 `default=N`，直接一路按键盘回车键即可。

---

### 第四步：把 `phone_client` 文件夹拷入手机

你可以通过以下任一方式把电脑上的 `phone_client` 文件夹放到手机上：
1. **手机用数据线连电脑**：
   - 将电脑上的 `phone_client` 文件夹复制到手机的 **内部存储根目录** 或 **Download 文件夹**。
2. **通过 QQ/微信/网盘发送**：
   - 把 `phone_client` 文件夹或压缩包发送到手机，保存到手机存储目录。

**在 Termux 中进入该文件夹：**
如果你放到了手机的 `Download` 目录中，在 Termux 里输入：
```bash
cd ~/storage/shared/Download/phone_client
```
如果你直接放在手机根目录，输入：
```bash
cd ~/storage/shared/phone_client
```

**把 `phone_agent.py.b64` 还原成 `phone_agent.py`**（这一步必须做，否则第六步会报找不到主程序）：

> **为什么会有这一步？** agent 要用 `am start` + `android.intent.action.VIEW` 组合拉起手机浏览器打开渲染页，
> 火绒 HIPS 会**按文件内容**识别这个组合并直接删掉这样的 `.py` 文件（电脑端和手机端同理）。
> 所以仓库里把它以 Base64 文本 `phone_agent.py.b64`（46290 字节）的形式存放，拷到手机后再还原。

```bash
base64 -d phone_agent.py.b64 > phone_agent.py
```

> ⚠️ 必须在 `phone_client` 目录里执行（要和 `.b64` 文件同目录）。
> 如果还原出来的 `phone_agent.py` 又被安全软件删了，先把手机安全软件对这个目录的防护/实时扫描关掉再跑。

输入 `ls` 回车，看到有 `phone_agent.py`、`config.json` 等文件即表示成功进入！
可以顺手确认还原成功（应输出一个正整数，表示匹配到 `_on_launch_url` 的行数）：

```bash
grep -c _on_launch_url phone_agent.py
```

---

### 第五步：修改配置填入服务器 IP

输入以下命令查看并编辑配置文件：

```bash
nano config.json
```

在打开的编辑器中，找到这两行：
```json
"server_host": "127.0.0.1",
"server_port": 8778,
```
- **手机与机器人在同一个 WiFi 下**：把 `127.0.0.1` 改成电脑的局域网 IP
  （电脑上 `ipconfig` 查，例如 `192.168.1.100`）。
- **机器人跑在云服务器上（本文档推荐场景）**：填入服务器的**公网 IP 或域名**，
  例如 `"server_host": "YOUR_SERVER_HOST"`，端口保持 `8778`。
  前提是云厂商安全组已放行 `TCP:8778`。
- `token`：与服务器模块 `config.py` 里的 `PHONE_BRIDGE_TOKEN` 保持一致
  （务必改掉默认值，不要让公网端口裸奔）。

**保存方法**：
- 按键盘上的快捷键：`Ctrl` + `O`，然后按回车保存；
- 再按 `Ctrl` + `X` 退出编辑器。

---

### 第六步：运行 Agent 并常驻后台

在 `phone_client` 目录下，运行启动脚本：

```bash
bash start_agent.sh
```
（或者直接运行：`python phone_agent.py`）

当看到控制台输出（第一段横幅为原文，末尾两行日志带时间戳与 `[INFO]` 前缀）：
```text
============================================================
  Maimai Phone Agent (Termux 手机端后台服务已启动)
  目标服务器: YOUR_SERVER_HOST:8778
  配置视频路径: ['/sdcard/maimai_videos', ...]
============================================================
...
2026-10-16 18:24:32 [INFO] [+] 连接服务器成功！WebSocket 通道已建立。
2026-10-16 18:24:32 [INFO] 心跳保活协程已启动，间隔 10 秒
```
**恭喜你，手机端 Agent 服务已连接成功！**

## 二、视频存放与命名规范

**主目录**：`/sdcard/Download/maimai/` —— 手机 Chrome 渲染出的成品会自动落在这里，
文件管理器的「下载」里能直接看到。

Agent 也会扫描这几个目录（`phone_client/config.json` 的 `video_directories`）：
`/sdcard/maimai_videos`、`/sdcard/Download/maimai_videos`、`/sdcard/Download`、`./videos`。
放哪都行，只要文件名符合下面的规则。

### 视频命名规则（支持以下方式，完全兼容）：
1. **标准规范（强烈推荐）**：`<曲目ID>_<难度槽位>.mp4`
   - 手机端 `worker.html` 工作页渲染出的视频会自动按此规则命名，**直接落进手机**！
   - 难度槽位编号（与官方 simai 槽位一致，**请一律按 2~7 命名**）：
     - `Basic (绿谱)`：`2`（例如 `11879_2.mp4`）
     - `Advanced (黄谱)`：`3`（例如 `11879_3.mp4`）
     - `Expert (红谱)`：`4`（例如 `11879_4.mp4`）
     - `Master (紫谱)`：`5`（例如 `11879_5.mp4`）
     - `Re:Master (白谱/DX)`：`6`（例如 `11879_6.mp4`）
     - `Utage (宴谱)`：`7`（例如 `11879_7.mp4`）
2. **难度英文别名规范**：`<曲目ID>_<难度英文/中文>.mp4`
   - 例如：`11879_master.mp4`、`11879_remas.mp4`、`11879_exp.mp4`、`11879_紫.mp4`
3. **曲目通用命名（单曲唯一）**：`11879.mp4`
   - 只在上面两种都找不到时兜底，而且**必须文件名里完全不含难度信息**。

> ### ⚠ 难度匹配是「精确」的，不会猜
> Agent 会从文件名里解析出难度，**只有和请求的难度完全一致才会回传**。
> 请求红谱（4）时若手机里只有 `11879_5.mp4`，Agent 会明确回「没预录」，
> 让服务器转去现场渲染，**绝不会把紫谱的成片当红谱发出去**。
>
> 这个规则是修出来的（早期版本用子串匹配，`11422_5.mp4` 会被请求红谱(4)时误命中，
> 因为 `5` 里没有 `4` 但别名表里 `4` 对应 `expert`，字符串判断会串味；
> 更早的兜底规则甚至是「该曲目只有一支视频就直接发」，完全不看难度）。
> 现在改成严格 `<曲目ID>_<难度>` 前缀解析，拿不准就回「没预录」。
>
> **顺带的好处**：将来 simai 真出现 8 号槽位，`11879_8.mp4` 也能被正确匹配，
> 不需要改 Agent。但服务器侧的 `_VALID_DIFF_SLOTS` 白名单仍只放行 2-7，
> 届时需同步放开（见《手机渲染部署指南》）。

## 三、手机后台防杀与息屏常驻指南（关键！）

安卓系统通常有省电机制，为了让 Agent 在手机锁屏后依然不断开连接，请进行以下简单设置：

1. **获取 Termux 唤醒锁（自动）**：
   - 脚本 `start_agent.sh` 会自动调用 `termux-wake-lock`，Termux 通知栏会显示 `(wake lock held)` 图标，防止 CPU 深度休眠。
2. **手机系统电池设置**：
   - 长按桌面上的 Termux 图标 -> 点击【应用信息】->【省电策略 / 电池管理】-> 设置为【**无限制**】（或【允许后台高耗电】）。
   - 在手机多任务切换界面，将 Termux 卡片**下拉加锁**。
3. **后台挂起运行（关闭终端窗口也不中断）**：
   如果你希望关闭 Termux 终端窗口后它依然在后台静默运行，可以使用 `nohup`：
   ```bash
   nohup python phone_agent.py > agent.log 2>&1 &
   ```
   查看运行日志：
   ```bash
   tail -f agent.log
   ```
   需要停止后台服务时：
   ```bash
   pkill -f phone_agent.py
   ```

## 四、常见问题与排查 (FAQ)

### Q1: 运行提示 `连接服务器失败 [xxx:8778]: Connection refused`
- **检查 1**：电脑/服务器端的 HoshinoBot 是否已启动？端口 8778 是否已处于监听状态？
- **检查 2**：手机和电脑是否连在同一个路由器/WiFi？（手机与电脑需局域网互通，可在电脑命令行运行 `ping 手机IP` 检查连通性）。
- **检查 3**：电脑的 Windows 防火墙是否拦截了 8778 端口？可在防火墙设置中允许 Python 或入站放行 8778 端口。

### Q2: 日志出现 `当前没有可用的视频存储目录！请检查目录权限或配置。`
- 这表示 Agent 对 `config.json` 里 `video_directories` 列出的目录全都打不开或扫不到视频；
- 在 Termux 中重新输入 `termux-setup-storage` 并务必点击手机弹窗中的【允许】（否则读不了 `/sdcard`）；
- 再确认至少一个视频目录真实存在、里面有视频文件（命名见第二节）。

### Q3: 收到任务提示 `未检索到曲目 xxxx 的视频文件`
- 检查视频文件是否已经放入 `/sdcard/maimai_videos/` 或手机的 `Download/` 目录；
- 检查文件名是否符合 `<曲目ID>_<难度>.mp4`（如 `11422_3.mp4`）；
- 检查文件是否**完整**：服务器会按曲库权威时长校验，时长远低于该曲实际长度的文件（例如 10 秒的测试片）
  会被判定为残缺并拒收，日志里会写 `video duration mismatch`。请重新渲染完整版本。

### Q4: 服务器日志出现 `上传的视频不合格，拒绝入库`
这是**预期行为**，不是故障。服务器会用 `data/catalog.json` 里该曲该难度的权威时长来核对你上传的视频：
实际时长 ÷ 应为时长 必须落在 `0.75 ~ 1.35` 之间。不满足就说明这个文件不是完整全曲（常见的 10 秒测试片比值只有 0.06）。
被拒的文件会移到服务器的 `cache/mp4/rejected/` 目录，方便你排查。重新渲染一次完整版本即可。
